# MOD 再現度メモ (原作 original-game との対応)

原作の仕様は `original-game/docs/TRIALS-AND-WEAPON-ARTS.md` と `original-game/src/game/*.ts` が正。
MOD 側の数値・規則はこの文書の対応表に従い、純粋な計算式は `GameData.java` に集約している
(テスト: `src/test/java/com/abyssalloot/GameDataTest.java`)。

## 今回の再現度改善

| 項目 | 原作 | 旧MOD | 今回のMOD |
|---|---|---|---|
| 奥義の威力 | 奥義ごとの倍率で与ダメ | 武器命中の処理で威力を上書きされ倍率が消えていた | 奥義・二次反応は `WeaponArts.artHurt` 経由で威力をそのまま使う |
| 奥義ゲージ | 与ダメ(残HPまで)×3/Atk・上限7、被ダメ(残HP/最大HP×35)、奥義自身・罠・二次反応は増えない | 撃破ごとの固定値に魂倍率(×2.46)・契約×3まで掛けていた | 与ダメ・被ダメで蓄積。鈍痛×0.70は全ゲージ獲得に適用 |
| 魂(報酬) | 呪印146%・難易度・モード倍率を報酬に適用 | ゲージ側に適用 | 魂の欠片の個数に適用 (`RunManager.rewardMult`) |
| 乱舞 | エリート率 ×1.9 (上限90%)、基礎 0.05+0.014×層 | 3体に1体の固定 | 原作式の確率抽選 (`GameData.eliteChance`) |
| 飢餓 | 戦闘回復・回復アイテム・休息・層移動の回復量 ×0.58 | 層移動のみ | `RunManager.heal` で全回復経路を統一 |
| 注視 / 深淵 | 索敵・射撃開始距離 ×1.45 / ×1.10 | 未実装 | 敵の FOLLOW_RANGE に反映 |
| 深淵 (移動) | 敵移動 ×1.10 | 未反映 | 疾風と合わせて敵移動に反映 |
| 敏捷 | 移動 +1.5%/点、回避CT -1%/点 | 回避CT固定 | 職業別の回避CT (`HeroClass.dashCd`) を敏捷で短縮 (下限0.28s) |
| 職業の移動速度 | 剣聖250・魔導士244・忍者300・聖騎士226・銃魔256 | 概算値 | `HeroClass.moveSpeed` から換算 |
| 幸運 | 運+7/点、素材獲得量+4%/点 (端数は確率丸め) | 会心率に誤って加算 | 会心からは外し、武器ドロップ率 (+0.0007/運) と魂の欠片数に反映 |

## 検証状況

- 原作 TypeScript: `node --test tests/abyss-regression.cjs` 26件すべて通過 (変更なし)。
- MOD (Java): Gradle / NeoForge / Maven に接続できない実行環境のため、**ビルドと JUnit は未実行**。
  代わりに tree-sitter-java で全 Java ファイルの構文を検査し、追加した式は `GameDataTest` の期待値を手計算で照合した。
  実機では `./gradlew test build` (デーモンを残さない場合は `--no-daemon`) で必ず確認すること。

## まだ原作と差がある点 (次の改良候補)

- 敵種: 通常敵の種類と重みは原作ENEMIESの簡易版 (Enemies.ROSTER)。
- 罠: 針罠・岩罠の予兆時間と範囲は簡易版 (感圧は一度きり)。
- 破壊物 (赤水晶・青瓶・祭壇) と層間イベント (休息・誓い・商店・鍛造) は簡易版。
- 奥義の判定形状: 原作の `planWeaponArt` の角度・射程は近似。月牙斬の貫通・竜殺しの経路判定は未完全。
- 層の異変 (FLOOR_MUTATIONS) の種類・効果は簡易版。
- 呪印: 選択UIは未実装 (`/abyss sigil` のトグルのみ)。重複禁止・8枚上限は集合で満たすが、原作の「出撃登録 (`/api/expeditions`) で条件を固定し、報酬を再計算する」仕組みは未移植。
- 魂の報酬: 原作の run reward (階層・撃破・スコア) の集計式は未移植。現状は欠片数で代替。

## 第2段 (アセット・操作・護衛兵)

- テクスチャ: `tools/generate_textures.py` で16x16のドット絵12武器+魂の欠片を生成 (武器ごとに形状を変えている)。モデルJSONも同スクリプトが出力。
  - 既知の弱点: 刀の刃が細く見える。描き直し候補。
- 操作: E=武器奥義、Q=必殺技 (仕様どおり)、C=回避 (仕様はShift/Spaceだが、Shiftはスニーク、Spaceはジャンプと衝突するため暫定)。
- 鉄壁の護衛兵 (4層〜、5体に1体): 前方±60°からの被ダメ30%、側面・背面135%。`CombatHandler.onGuardHit` (LOW優先度)。
  - 未再現: 原作の「向きの転換に時間がかかる」挙動 (MCのAIは即座に振り向く)。

## 第4段 (出撃前設定メニュー)

- `/abyss menu`（参加時案内・操作説明からも開ける）: 職業・呪印(8種)・モード・難易度をチャットのクリックボタンで選び、`[出撃！]` で開始。現在値は色で示す（緑=選択中）。
- 呪印の魂倍率は画面に表示。切替後は `[メニュー更新]` で再表示。
- 未対応: ゲーム内GUI画面（ドラッグ式の装備比較など）は未着手。

## 第5段 (敵の再構成・骸骨の蘇生師・呪われた召喚門)

構成 (リファクタリング):
- `Enemies.java`: 敵の定義表 (`ROSTER`)、出現抽選 (`pickSpec`)、能力値 (`scaleFor` / `apply`)、召喚子 (`spawnChild`)、精鋭化を集約。
- `EnemyAI.java`: 特殊敵の毎tick挙動 (10tickごと)。
- `RunManager.spawnWave`: 上記を呼ぶだけに薄くした (旧 `pickMob` と護衛兵の個別処理を削除)。
- `GameData`: 特殊スロット (`specialSlotRole`) と層倍率 (`floorHpScale` / `floorDmgScale`) を純粋関数に。

実装:
- 骸骨の蘇生師 (6層〜、i%7==5): 5m以内なら離れ、10m以遠なら寄る。8m程度の中距離を保つ。約7秒ごとに朽ちた兵を最大2体、生存する子は最大4体。
- 呪われた召喚門 (7層〜、i%9==8): 移動も攻撃もしない (NoAI)。約5.8秒ごとに最大2体、生存する子は最大6体。HPは通常の6倍。
- 子 (朽ちた兵) は `abyss_summon` タグを持ち、撃破してもウェーブ数に数えない (転移門の早開き防止)。
- 門の撃破で実績「門を断つ者」。
- 画面内の敵は48体まで (`Enemies.SCREEN_CAP`) で召喚を止める。

未検証: Java のビルドは実行できていない。`GameDataTest` の追加分 (スロット・層倍率) は手計算で期待値を確認済み。

## 第6段 (護衛兵の回頭・感圧罠の予兆)

- 鉄壁の護衛兵: 毎tickで最寄りのプレイヤーへ最大4度/tick (約80度/秒) しか向きを変えない (`EnemyAI.tickGuards`)。被ダメ判定は向きで決まるため、側面への回り込みが有効になる。MCの標準AIが向きを変えるのとの競合は未検証。
- 感圧罠: 作動後1秒の予兆 (煙) を経て爆発 (従来は即爆発)。
